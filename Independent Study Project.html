Designing and Analyzing a Financial Database

Currency and Market Data for the Kazakhstan Context

🎯 Background & Motivation

One of the most practical skills a business systems graduate can develop early on is the ability to work with structured data. Financial data is everywhere: banks use it, regulators publish it, and businesses encounter it daily. Kazakhstan presents an interesting environment for this. The National Bank of Kazakhstan (NBK) publishes official exchange rate data for the tenge (KZT) against major world currencies on a daily basis and makes it freely accessible.

Over five weeks, you will move through the full cycle: understanding relational databases, designing a schema, populating it with real data from NBK, and running analytical queries. The project is intentionally scoped to be achievable locally without cloud accounts.

Learning Objectives

By the end of the project, you should be able to:

1

Explain core concepts of relational databases (tables, primary/foreign keys, normalization) without looking them up.

2

Draw and justify a simple Entity-Relationship (ER) diagram for a defined business problem.

3

Write SQL queries of moderate complexity (SELECT with JOINs, GROUP BY, aggregate functions, date filtering).

4

Retrieve structured data from a public financial source (NBK API) and load it into a local database.

5

Perform basic financial data analysis (trends, volatility) using SQL and optionally Python (pandas).

6

Produce a written technical report documenting design decisions clearly for reproducibility.

✔ In Scope

  • ▪ Design of a relational database schema (2–4 tables)
  • ▪ Data sourcing from NBK open data
  • ▪ Data loading via CSV import or Python script
  • ▪ SQL query writing and analysis
  • ▪ Short written report and ER diagram

✖ Out of Scope

  • ▪ Web applications or dashboards
  • ▪ Real-time data streaming
  • ▪ Machine learning or forecasting models
  • ▪ Connecting to KASE trading systems

These topics are suitable for follow-up projects, but stretching the timeline now is unreasonable.

Report Sections (2,000–3,500 words)

A technical document requiring clear structure and precise language.

1

Introduction

What is the project about and why does it matter? Be specific.

2

Data Source and Collection

Where data comes from, NBK API returns, retrieval methods, and handling of data quality issues.

3

Database Design

Present ER diagram. Justify tables, relationships, and normalization decisions.

4

SQL Analysis (Longest section)

For each query: state business question, show formatted SQL, show sample output, interpret result.

5

Key Findings

Meaningful takeaways about KZT exchange rate behavior in the past 12 months based on your data.

6

Reflections, Next Steps & References

What to do differently, unanswered questions, and citations for tools/tutorials.

A note on writing: Write in your own voice. Be precise rather than overly academic. If a decision was made for pragmatic reasons, state it honestly.

Assessment Criteria & Academic Integrity
